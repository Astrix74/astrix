语言模型本身只是把一段文本映射成另一段文本。而“智能体”会读懂任务，决定要做什么，通过工具去做，查看发生了什么，然后继续下去，直到把事情做完。两者的区别不在模型的权重里，而在包裹着模型的那个程序里。这个程序就是 **harness**：调用模型的循环、允许它使用的工具，以及每一步决定把什么放进它上下文窗口的那些决策。

编程智能体是最清楚的例子。同一个模型，既可以是一个聊天助手，也可以是一个横跨十几个文件修好一个失败测试的智能体；变的是 harness。随着模型越来越强，一个好用的智能体和一个让人抓狂的智能体之间的差别，越来越多地来自 harness 的设计。

这个系列讲每个 harness 都有的几个部分：智能体循环、智能体与工具之间的接口，以及上下文工程，也就是模型能看到什么、看不到什么。

**适合谁读**：用语言模型做开发、或者想弄懂自己所用智能体的开发者。《从第一性原理理解 Transformer》解释了为什么上下文长度和 token 顺序在这里如此重要；不过如果你已经知道上下文窗口是什么，也可以直接从这个系列读起。

**怎么读**：按顺序读。示例都是小型 Python 程序，用一个替身模型代替真实的模型，不需要 API key 就能运行，所以你能看清循环的每一步。
